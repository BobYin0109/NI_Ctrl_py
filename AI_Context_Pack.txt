1. Current Goal

The user is running triggered fluorescence Z-stack imaging. Python controls a PI E-727.3CD piezo stage and an NI PCIe-6353 DAQ. HCImageLive controls/saves frames from a Hamamatsu CMOS camera. The normal production scan is:

- Arm HCImageLive Sequence in external-trigger Time Lapse mode.
- Python reads the current PI Z at scan start and treats it as the center. It then moves from current_z - 1.000 um to current_z + 1.000 um in fixed 0.010 um steps.
- At each Z, Python waits for the PI controller to report target reached, waits an extra settle time, then sends one TTL pulse from NI to the camera external trigger.
- HCImageLive saves one TIFF per trigger.
- At the end, Python returns PI Z to the scan-start current_z center.
- After every scan, verify Z returned to the scan-start center and verify the TIFF directory contents and image metrics.

The user explicitly requested: after every scan, always check whether the stage returned to the correct center, then check the directory TIFFs are normal and meet requirements, including whether image content shows correct Z information. New rule from 2026-06-26: if the user manually refocuses before a scan, that current Z is the new center. The nominal 49/50/51 config is interpreted relative to that current center.

6. Meaning of HCImageLive Settings

Speed:
- HCImageLive camera readout speed, not PI movement speed and not NI trigger speed.
- Successful scans used Speed = 2. Keep Speed = 2 unless there is a clear reason to re-characterize.

Mono vs RGB Color / 2-Band:
- Current workflow uses Mono: 1 Channel.
- Earlier RGB Color: 2-Band looked like it saved combined/multi-channel images and appeared to need two camera triggers per saved TIFF; file size was about 24 MB.
- If using 2-Band in future, likely set triggers_per_position=2 to keep one saved image per Z position. For current production, keep Mono: 1 Channel and one trigger per Z.

9. Code Behavior / Timing

PI movement:
- src\ni_ctrl_py\pi_stage.py uses MOV and then pitools.waitontarget(...).

Scan loop:
- src\ni_ctrl_py\scan.py reads current Z at scan start when use_current_z_as_center=true, resolves the nominal 49/50/51 range into current_z-1/current_z/current_z+1, then moves to each resolved Z.
- It waits until target is reached.
- It sleeps settle_time_s (currently 0.5 s).
- It sends trigger_pulse_s TTL pulse on Dev1/port2/line5.
- In a finally block, it moves Z back to the scan-start current Z center when use_current_z_as_center=true.

Answer to user concern about moving too fast:
- Under normal conditions, Python should not trigger before the PI stage reaches target because it waits for the PI controller target state, then waits an additional 0.5 s settle time.
- A problem could still happen if the PI controller falsely reports on-target, there is mechanical settling beyond the configured wait, HCImageLive drops triggers, or a folder contains extra/missing files. That is why image and count verification after each scan is mandatory.

12. Common Failure Modes and Recovery

If no TIFFs appear after Python scan:
- Do not blindly rerun full scan.
- Stop Sequence in HCImageLive if active.
- Stop Live.
- Set AutoSave folder and click OK in AutoSave Properties.
- Confirm AutoSave checked, TIFF, to Disk, Live Image, End Frame expected count.
- Confirm Capture Mode = External Edge Trigger, Pos, Delay 0 us.
- Click Start in Sequence.
- Run the 3-pulse diagnostic.
- If 3 TIFFs appear, then arm a clean folder and run full production scan.

If HCImageLive hangs on Stop:
- It previously happened. User requested ending HCImageLive. Killing/restarting HCImageLive may be needed, but avoid doing this unless user confirms, because it affects camera session state.

If Live looks like noise after scan:
- First query PI qPOS. It should be near Z=50.
- If Z is 50 but live looks noisy, possible causes include HCImageLive still being in external trigger mode, light source/shutter/filter state, display contrast, or the actual best focus not being at 50. In folder 1, best sharpness was near 49.12.

If Nikon lock focus is on:
- Turn it off before Z-stack scans. Otherwise images may repeat because microscope focus follows the Z change.

If PI MikroMove is open:
- It can occupy the PI controller connection. Earlier the user closed MikroMove before Python control. Keep other PI control software closed when Python needs to connect.
